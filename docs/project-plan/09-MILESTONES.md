# 里程碑、团队协作与风险

## 1. 总体路线

以下周期按 3 至 4 名核心成员并行估算。Coding Agent 可以缩短部分工程时间，但不能跳过退出条件。

| 阶段 | 目标 | 参考周期 |
| --- | --- | ---: |
| M0 | 工程基线 | 1 至 2 周 |
| M1 | 战斗沙盒 | 4 至 6 周 |
| M2 | Vertical Slice | 8 至 10 周 |
| M3 | Alpha 内容与系统 | 10 至 14 周 |
| M4 | Beta 内容完成 | 12 至 16 周 |
| M5 | 发布候选 | 6 至 8 周 |

总周期约 10 至 14 个月，取决于正式美术和动画产能。

## 2. M0：工程基线

目标：

- 固定 Godot 4.7.1。
- 建立目录、输入、碰撞层、日志、数据 Resource 和测试入口。
- Windows Debug 构建可启动。

退出条件：

- 新机器按 README 能在 30 分钟内运行工程。
- Headless 导入、数据校验和空测试套件通过。
- 键盘和手柄输入可被调试场景识别。
- CI 能产出 Windows Debug 包。
- licenses 目录和第三方资产清单存在。
- 已建立界面清单和页面信息架构草案；此时不要求高保真设计。

## 3. M1：战斗沙盒

目标：

- 刃契者基础移动、跳跃、三连段、闪避和一个技能。
- 训练假人、命中反馈、状态调试和伤害统计。
- 一个近战敌人。
- Figma 低保真工作与战斗实现并行：页面流程、HUD 信息层级和手柄焦点草案。

退出条件：

- 03-COMBAT-DESIGN.md 的战斗沙盒条件全部通过。
- 30 分钟连续对战无状态锁死。
- 攻击帧数据来自 Resource。
- 输入缓冲、命中去重、闪避无敌和存档基础测试通过。
- UX-001、UX-002 通过评审，HUD 不遮挡战斗关键信息。
- 灰盒手感评审确认后才允许扩展内容。

### M1 → M2 设计门禁

进入 M2 的 UI 编码前必须完成：

- UID-001：Figma 视觉基础和组件库。
- UID-002：Vertical Slice 高保真界面与可点击流程。
- 1920×1080 与 1280×720 两套关键布局。
- 键鼠和手柄焦点导航说明。
- HUD 在真实战斗沙盒截图上的可读性验证。

未通过该门禁时，可以继续非 UI 的 M2 后端任务，但不得自行设计并固化正式界面。

## 4. M2：Vertical Slice

目标：

- 沉降工厂 7 房间。
- 刃契者 8 技能和 4 个敌人。
- 炉心看守首领。
- 基础装备、掉落、结算、灰港菜单、设置和存档。
- 第一轮正式视觉与音频。
- 按冻结的 Figma 规范实现全部 Vertical Slice 界面并完成 UID-003 还原验收。

退出条件：

- 新存档到结算完整可玩 5 次，无阻断问题。
- 键鼠和手柄各完成一次全流程。
- 目标测试机 1080p 稳定 60 FPS。
- 存档中断、损坏和备份恢复通过故障测试。
- Figma 设计还原、手柄焦点、720p 与 1080p 布局验收通过。
- 至少 10 名外部或非开发成员试玩并完成反馈。
- 80% 测试者能在 3 分钟理解基础操作。

M2 是项目继续或缩减的正式决策门。

## 5. M3：Alpha

目标：

- 增加铳械师。
- 完成前 3 个区域，共 9 个地下城。
- 完整装备、制作、技能升级和难度系统。
- 敌人基础库达到 15 种。

退出条件：

- 从新档到第三地区域首领无阻断。
- 两个职业均能通关全部已有内容。
- 所有主要系统功能完成，不再新增大型系统。
- 关卡、物品、敌人可通过数据和工具稳定创建。
- 性能和内存无随房间数量增长的泄漏。

## 6. M4：Beta

目标：

- 增加纹术师。
- 5 个区域、15 个地下城和最终首领内容完成。
- 全部正式 UI、音频、美术与文本进入游戏。
- 困难模式和通关后挑战完成。

退出条件：

- 内容锁定，不再新增职业、区域或核心系统。
- 三职业完整通关测试通过。
- 所有占位资源有明确替换计划。
- 全流程存档升级测试通过。
- P0 问题为零，P1 问题有关闭计划。

## 7. M5：发布候选

目标：

- 只修复问题、平衡和优化。
- 完成许可证、署名、隐私说明与商店素材。
- 建立发布和回滚流程。

退出条件：

- 连续 7 天测试无新增崩溃或存档丢失。
- P0 和 P1 问题为零。
- 目标硬件完成 3 个职业全流程性能测试。
- 全部第三方资源授权审核通过。
- Release 包不包含调试工具、源素材或占位资源。

## 8. 工作流

每个任务：

1. 从 10-BACKLOG.md 选择依赖已完成的 ID。
2. 写出本任务的实现边界和测试计划。
3. 用最小灰盒资源实现。
4. 完成自动化测试。
5. 按验收条件人工检查。
6. 更新相关文档和变更记录。
7. 提交合并请求，不顺带重构无关模块。

## 9. 决策门

| 时间点 | 必须回答 |
| --- | --- |
| M1 结束 | 战斗手感是否足以支撑内容生产？ |
| M2 结束 | 玩家是否愿意重复游玩？美术产能是否匹配？ |
| M3 结束 | 三职业计划是否仍现实？是否削减区域？ |
| M4 中期 | 是否有足够时间打磨，而不是继续加内容？ |

如果 M2 外部试玩的重复游玩意愿低于 50%，先修正战斗与流程，不进入 M3。

## 10. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 动画产能不足 | 高 | 高 | 先做单职业切片；复用基础骨架；减少非战斗动作 |
| 战斗手感迟迟不稳定 | 中 | 极高 | M1 独立沙盒；不提前做内容 |
| 三职业导致测试量爆炸 | 中 | 高 | M3 决策门可把 1.0 缩减为 2 职业 |
| VFX 遮挡预警 | 中 | 高 | 建立颜色层级和最低特效验收 |
| 存档升级破坏进度 | 中 | 极高 | schema、备份、迁移和故障注入测试 |
| 关卡大量重复 | 中 | 高 | 每区一个主机制；手工房间；限制换色敌人 |
| AI 生成代码架构漂移 | 高 | 高 | AGENTS.md、任务 ID、文档优先级和小 PR |
| 使用无授权素材 | 低 | 极高 | 资产清单、许可证门禁和占位扫描 |
| 范围持续扩张 | 高 | 极高 | 非目标清单；任何新增必须替换等量内容 |

## 11. 范围变更

新增任何职业、平台、核心系统或区域，必须提交变更记录：

- 变更目的。
- 玩家价值。
- 替代方案。
- 受影响任务与文档。
- 新增工作量。
- 为保持工期要删除的等量内容。
- 决策人与日期。

未经记录的范围变化不得进入开发分支。

## 12. 问题优先级

| 级别 | 定义 |
| --- | --- |
| P0 | 崩溃、存档丢失、无法通关、许可证问题 |
| P1 | 核心战斗错误、严重性能下降、控制器无法操作 |
| P2 | 局部机制、UI、平衡或表现问题 |
| P3 | 轻微视觉、文本或体验优化 |

M2 对外试玩前 P0、P1 必须为零。
