# Figma UX/UI 工作流

## 1. 定位

Figma 负责界面信息架构、操作流程、视觉系统、组件状态、交互原型和开发交接。它不负责角色动作、场景原画、战斗特效或 Godot 中的最终动画实现。

Figma 不是开发结束后的美化环节。正确顺序是：

1. M0 确定页面清单。
2. M1 与战斗沙盒并行完成低保真流程和 HUD。
3. M1 结束后完成组件库和 Vertical Slice 高保真设计。
4. M2 按冻结设计实现并进行实机还原验收。
5. M3、M4 只扩展设计系统，不整体推翻。

## 2. 阶段与交付物

| 阶段 | 任务 | 主要交付物 | 是否阻断代码 |
| --- | --- | --- | --- |
| M0 | UX-001 准备 | 页面清单、用户流程草案 | 不阻断基础工程 |
| M1 并行 | UX-001、UX-002 | 完整流程、HUD 低保真、焦点草案 | 不阻断战斗沙盒 |
| M1→M2 门禁 | UID-001、UID-002 | 视觉基础、组件库、高保真、可点击流程、开发标注 | 阻断正式 UI 编码 |
| M2 | UID-003 | Godot 对照截图、差异清单、批准记录 | 阻断 Vertical Slice 验收 |
| M3/M4 | 增量页面 | 新职业、新区域和通关后界面 | 按功能阻断对应 UI |

## 3. Figma 文件结构

建议一个主文件，按以下 Page 组织：

| Page | 内容 |
| --- | --- |
| 00 Cover & Status | 项目、版本、负责人、冻结状态、变更记录 |
| 01 Foundations | 颜色、字体、栅格、间距、圆角、阴影、图标和动效原则 |
| 02 User Flows | 新游戏、继续、灰港、地下城、失败、结算和设置流程 |
| 03 Wireframes | 所有页面的低保真结构 |
| 04 Components | 组件、变体、状态和使用说明 |
| 05 Combat HUD | 普通战斗、精英、首领、教程和可访问性变体 |
| 06 Screens | Vertical Slice 高保真界面 |
| 07 Prototype | 键鼠和手柄主要可点击流程 |
| 08 Dev Handoff | 冻结画面、尺寸、切图、Token 和 Godot 映射 |
| 99 Archive | 已废弃方案；不得与当前冻结稿混用 |

每个正式 Frame 使用统一命名：

    平台/分辨率/流程/页面/状态/版本

示例：

    PC/1920x1080/Combat/HUD/Boss/v1
    PC/1280x720/Hub/SkillLoadout/Default/v1

## 4. UX-001：页面信息架构

必须覆盖：

- 启动和主菜单。
- 三个存档槽。
- 新游戏与继续。
- 灰港首页。
- 选关与难度。
- 技能配置。
- 装备、背包、比较、锁定和分解。
- 工坊、强化和首领徽记兑换。
- 战斗 HUD。
- 教程提示。
- 暂停与设置。
- 失败、重试和返回灰港。
- 结算、评分和奖励。
- 图鉴与帮助。

验收：

- 任何页面均有明确进入与退出路径。
- 关键流程只用键盘或手柄也能完成。
- 破坏性操作有预览与确认。
- 不依赖鼠标 Hover 才能理解关键信息。
- 页面名称与 GDD、Backlog 保持一致。

## 5. UX-002：HUD 低保真

HUD 必须放在真实战斗沙盒截图上设计，而不是空白画布。

必须验证：

- 玩家生命和职业状态。
- 四个技能、冷却和输入提示。
- 终极能量。
- 当前房间目标。
- 连击和伤害信息。
- 精英韧性。
- 首领生命、阶段和机制提示。
- 教程文本。
- 拾取与短时通知。

低保真阶段只确定信息优先级、位置、尺寸、遮挡和交互，不确定最终纹理和装饰。

验收：

- 玩家、敌方预警和地面危险不被遮挡。
- 1920×1080 与 1280×720 均能容纳关键内容。
- 手柄提示不会与技能冷却混淆。
- 普通、精英和首领三种 HUD 状态可区分。

## 6. UID-001：视觉基础和组件库

### 6.1 Design Tokens

至少建立：

- color/background、surface、text、accent、danger、warning、success、focus。
- spacing/2、4、8、12、16、24、32、48。
- radius/small、medium、large。
- type/title、heading、body、caption、number。
- opacity/disabled、overlay、subtle。
- motion/fast、normal、slow。

命名表达用途，不用 Blue500 之类只有外观含义的名称作为最终语义 Token。

### 6.2 组件

至少包含：

- Button。
- Icon Button。
- Tab。
- List Row。
- Equipment Card。
- Skill Slot。
- Progress Bar。
- Health Bar。
- Boss Bar。
- Tooltip。
- Modal。
- Toast。
- Input Prompt。
- Slider。
- Toggle。
- Dropdown。
- Save Slot。
- Item Compare Panel。

### 6.3 状态

所有交互组件根据需要覆盖：

- Default。
- Hover。
- Focus。
- Pressed。
- Selected。
- Disabled。
- Loading。
- Empty。
- Error。

Focus 必须比 Hover 更明确，确保手柄导航可见。

## 7. UID-002：Vertical Slice 高保真

必须完成：

- 主菜单。
- 存档槽。
- 灰港首页。
- 选关。
- 技能配置。
- 装备与背包。
- 工坊。
- 战斗 HUD 的普通、精英和首领状态。
- 暂停。
- 设置与改键。
- 失败与重试。
- 结算与奖励。

关键页面同时提供 1920×1080 和 1280×720。其他常用 16:9 分辨率由约束规则推导。

可点击原型至少覆盖：

1. 主菜单到新游戏。
2. 灰港配置技能后进入地下城。
3. 战斗暂停后修改设置并返回。
4. 失败后重试。
5. 通关后查看奖励并返回灰港。
6. 仅用手柄焦点完成技能和装备配置。

## 8. 原创与资产规则

- 不照搬 DNF 或其他游戏的 HUD、技能框、图标、字体和菜单构图。
- Figma 中外部字体、图标库和素材必须登记许可证。
- AI 生成概念只作为探索，正式资产需要确认来源和可用范围。
- 占位图标明确标记 Placeholder，不得进入 Release。
- 导出资源使用小写英文、数字和下划线命名。

## 9. 开发交接

每个冻结界面必须提供：

- Frame 名称与版本。
- 目标分辨率。
- 栅格与安全区。
- Auto Layout 或等效约束。
- 组件实例，不使用无法追踪的大量复制图层。
- 文字样式和本地化扩展规则。
- 键鼠与手柄焦点顺序。
- 空、加载、错误和禁用状态。
- 动效意图、时长和是否可被可访问性设置关闭。
- 资源导出状态：正式、占位或无需导出。

Figma 命名与 Godot 映射建议：

| Figma | Godot |
| --- | --- |
| Screen Frame | 独立 Control 场景 |
| Component | 可复用 Control 场景 |
| Variant | Theme、状态或独立子场景 |
| Token | Theme Resource 或集中常量资源 |
| Prototype Flow | UI 状态机与输入 Context |

## 10. UID-003：Godot 实机还原验收

还原验收必须在运行中的 Godot 构建进行，不接受仅查看编辑器场景。

检查：

- 1920×1080 和 1280×720 截图对照。
- 容器约束和长中文文本。
- 鼠标、键盘和手柄焦点。
- 普通、Focus、Disabled、Loading、Empty 和 Error 状态。
- 动态生命、冷却、奖励数量和背包内容。
- 字幕 140%。
- 屏幕震动、闪光和伤害数字设置。
- 战斗最繁忙场景的 HUD 可读性。

差异处理：

- 实现错误：修复后重新验收。
- 引擎限制：记录原因和替代方案，由设计负责人批准。
- 设计在实机不可用：回到 Figma 修改并产生新版本，不让 Coding 私自决定。

## 11. 设计冻结

UID-002 通过后标记 Vertical Slice UI v1 Frozen。

冻结后允许：

- 修复可用性问题。
- 解决本地化溢出。
- 补齐遗漏状态。
- 无范围扩张的可访问性改进。

冻结后禁止：

- 未评审的整体换风格。
- Coding 自行调整布局和颜色系统。
- 为新增功能随意破坏现有组件 API。

任何重大修改记录：

- 变更原因。
- 受影响 Frame 和组件。
- 对 Godot 场景和 Backlog 的影响。
- 新版本号。
- 批准人与日期。

## 12. 插件启用时机

Figma 插件在 UX-001 正式开始前安装并授权即可，不需要在仓库和 M0 尚未启动时提前安装。

启用后用于：

- 读取已选定的 Figma 文件和 Frame。
- 核对组件、尺寸、文案和设计状态。
- 将设计差异转成明确的开发任务。
- 在 UID-003 中辅助还原检查。

插件连接不能代替设计评审，也不能自动决定产品范围。
