# 架构与产品决策记录

## ADR-001：离线单机

状态：接受。  
日期：2026-08-06。

决定：

- 只制作离线单机。
- 不建设账号、服务器、联机同步、PVP、排行榜或在线经济。

原因：

- 用户明确选择单机。
- 显著降低工程、测试、运维和内容平衡复杂度。
- 更适合先完成可玩的横版动作 RPG。

后果：

- 可随时暂停。
- 存档完全本地。
- 不以服务器权威或反作弊为设计前提。

## ADR-002：Godot 4.7.1 与 GDScript

状态：接受。  
日期：2026-08-06。

决定：

- 使用 Godot 4.7.1 Stable。
- 使用 typed GDScript。
- 使用 Compatibility renderer。

原因：

- 当前稳定维护版，适合 2D 项目。
- MIT 许可，商业发行边界清晰。
- GDScript 与 Godot 场景和 Resource 工作流紧密，降低原型和工具开发成本。

后果：

- 不使用 4.8 开发版本或 4.7.2 RC。
- 升级引擎必须独立分支并完成全量回归。

## ADR-003：手工固定地下城

状态：接受。  
日期：2026-08-06。

决定：

- 1.0 的主线地下城全部手工制作。
- 不做程序化房间拼接。

原因：

- 有利于教学、节奏、首领铺垫和性能控制。
- 避免为了重复游玩引入与核心体验无关的生成系统。

## ADR-004：三职业分阶段

状态：接受，可在 M2 决策门缩减。  
日期：2026-08-06。

决定：

- Vertical Slice 只做刃契者。
- Alpha 增加铳械师。
- Beta 增加纹术师。

原因：

- 先验证战斗和内容管线。
- 避免三职业并行放大动画和测试成本。
