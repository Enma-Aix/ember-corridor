# 验收测试计划

## 1. 目的

本计划用于验证项目是否达到里程碑退出条件。自动化测试负责公式、状态与数据一致性；人工测试负责手感、可读性、输入和完整流程。两者都不能省略。

## 2. 测试构建

| 构建 | 用途 |
| --- | --- |
| Debug | 碰撞框、AI 决策、帧数据、快速选关和日志 |
| Playtest | 接近 Release，但保留反馈编号和本地日志 |
| Release Candidate | 最终导出配置，不含调试入口 |

每次测试记录：

- Git commit。
- Godot 版本。
- 构建类型。
- 操作系统与硬件。
- 输入设备。
- 存档 schema_version。
- 测试用例、结果和问题 ID。

## 3. 最低环境矩阵

- Windows 10 x64，键鼠。
- Windows 11 x64，键鼠。
- Windows 10 或 11，XInput 手柄。
- 1280×720 窗口。
- 1920×1080 全屏和窗口。
- 60 Hz 显示器；有条件时补充高刷新率。

## 4. 启动与基础检查

| 用例 | 预期 |
| --- | --- |
| 首次启动，无设置和存档 | 进入主菜单，自动生成合法默认设置 |
| 非法数据资源 | Debug 构建明确报错并阻止开始游戏 |
| 切换全屏与窗口 | 不崩溃、不丢失焦点、不截断 UI |
| 键鼠切手柄 | 按键提示在一次有效输入后切换 |
| 退出并重启 | 音量、分辨率、按键与可访问性保持 |

## 5. 移动与输入

- 八方向移动速度与动画一致。
- 同时按相反方向时行为稳定。
- 失去窗口焦点后不保持移动或攻击。
- 输入缓冲边界 tick 与设计一致。
- 改键冲突有提示，不覆盖无法恢复的关键操作。
- 手柄断开后游戏暂停并提示，可切回键盘。
- 自动普通连击开启和关闭均可完成基本三连段。

## 6. 战斗

- 普通攻击三段命中、落空和提前输入均正确。
- 左右朝向的 Hitbox 完全镜像。
- 上下纵深边缘不会出现明显视觉命中但无伤害。
- 同一 hit_id 不重复结算。
- 暂停期间不推进 cooldown、无敌和攻击 tick。
- 闪避无敌开始前和结束后的命中均可复现。
- 浮空超过上限时强制落地。
- 首领阶段切换不造成攻击重复或状态丢失。
- 敌人失败后不继续造成伤害。

## 7. AI 与房间

- 同时高危险预警不超过设计上限。
- 镜头外敌人不释放强力攻击。
- 敌人找不到路径时能恢复或回到合法点。
- 清完波次后只打开正确出口。
- 房间重试恢复机关、敌人、门和音乐状态。
- 连续进入退出同一房间 20 次，无重复事件和单位残留。
- 结束最后一波与拾取奖励顺序稳定。

## 8. 成长与物品

- 升级、解锁技能、重置技能和重新分配均正确。
- 穿脱同一装备 100 次不累计属性。
- 满背包装备进入结算暂存。
- 批量分解不处理锁定、匠造和遗物装备。
- 强化始终成功，材料与返还数值正确。
- 固定 seed 产生固定掉落。
- 重新加载检查点不能刷新已确定奖励。
- 首领首次奖励和徽记兑换按规则执行。

## 9. 存档故障注入

必须保留自动生成的测试存档，不使用真实玩家存档测试。

| 故障 | 预期 |
| --- | --- |
| 写入 tmp 后模拟中断 | 下次启动使用原存档 |
| 当前存档截断 | 自动尝试 backup |
| 当前与 backup 都损坏 | 清晰提示，不影响其他槽 |
| 旧 schema 样例 | 按顺序迁移，关键数据一致 |
| 缺少可选字段 | 使用明确默认值 |
| 缺少必填字段 | 拒绝静默加载并记录字段路径 |

## 10. UI 与可访问性

- 测试构建对应明确的 Figma 页面版本或冻结日期。
- 720p 和 1080p 不截断关键按钮或文本。
- 所有界面仅用手柄可进入、操作和退出。
- 所有弹窗有默认焦点和明确取消行为。
- 屏幕震动设为 0 后完全停止。
- 降低闪光后危险区域仍清晰。
- 关闭伤害数字不影响连击和首领机制。
- 字幕 140% 时不越界。
- 关键信息不只通过颜色表达。
- HUD 使用真实战斗截图对照，关键信息优先级与 UID-002 一致。
- 按钮、技能槽、列表、弹窗、Focus、Disabled、Loading、Empty 和 Error 状态与组件库一致。
- 实现与 Figma 有意差异时，必须记录原因并由设计负责人接受，不得静默偏离。

## 11. 性能

标准压力场景：

- 1 名玩家。
- 12 个普通敌人。
- 2 个精英。
- 48 个活动 Hitbox 上限场景。
- 中等 VFX。
- 完整 HUD。

记录：

- 平均、1% low 和最差帧耗时。
- 物理帧是否积压。
- 场景加载时长。
- 房间切换前后内存。
- 高频对象数量。

判定：

- 目标机 1080p 稳定 60 FPS。
- 连续切换 30 个房间后内存不持续单向增长。
- 存档写入不造成可感知的战斗卡顿。

## 12. Vertical Slice 全流程脚本

1. 删除测试存档并首次启动。
2. 新建存档并完成基础设置。
3. 在灰港配置四个技能。
4. 完成沉降工厂七个房间。
5. 中途在 F04 返回主菜单并继续。
6. 在 F05 故意失败一次并重试。
7. 击败炉心看守并完成结算。
8. 穿戴装备、强化一次、兑换一次。
9. 重启游戏并验证全部进度。
10. 使用另一输入设备再次完成首领。

## 13. 问题报告

每个问题包含：

- 标题和优先级。
- 构建 commit。
- 环境和输入设备。
- 前置条件。
- 最短复现步骤。
- 实际与预期。
- 复现概率。
- 截图、视频或本地日志。
- 是否涉及存档、崩溃或授权。

## 14. 发布阻断条件

存在以下任何一个问题都不能发布：

- 已知崩溃。
- 已知存档丢失或无法恢复。
- 无法完成主线。
- 键鼠或手柄无法完成关键操作。
- 来源不明或无权使用的资源。
- Release 包包含调试入口、开发密钥或源素材。
- 目标硬件无法达到可玩的性能。
