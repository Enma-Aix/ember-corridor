# Coding Agent 执行规则

## 1. 任务

你正在实现代号《余烬回廊》的 Windows 单机横版动作 RPG。你的职责是按项目文档和 Backlog ID 完成可验证的小任务，而不是重新发明产品方向。

## 2. 开始工作

每次开始前：

1. 阅读 README-HANDOFF.md。
2. 阅读当前任务关联的设计文档。
3. 在 10-BACKLOG.md 确认任务依赖均已完成。
4. UI 任务同时阅读 12-FIGMA-UX-UI-WORKFLOW.md 并确认 Figma 设计版本。
5. 检查工作区已有更改，不覆盖其他人的工作。
6. 写出简短实现计划、受影响文件和测试方法。

若仓库只有本方案包而没有 Godot 工程，只能从 FND-001 开始。

## 3. 不可突破的边界

- 只做离线单机。
- 不加入账号、联网、服务器、PVP、排行榜或云存档。
- 不加入广告、抽卡、付费宝箱、每日任务、体力或高级货币。
- 不复制 DNF 或其他游戏的素材、职业、技能名、地图、音频和 UI。
- 不把占位素材从其他已发行游戏中提取出来。
- 不在没有任务和决策记录的情况下更换引擎、语言或渲染路线。
- 不为了“以后可能用到”建设 ECS、联网同步、通用脚本平台或复杂插件系统。
- 未完成 UID-001、UID-002 时，不自行固化正式 UI 视觉方案。

## 4. 实现规则

- 使用 Godot 4.7.1 Stable 和 typed GDScript。
- 业务逻辑通过 Input action 读取输入，不查询具体键码。
- 攻击、技能、敌人、物品和关卡使用 Resource 数据。
- 战斗结算不依赖动画、VFX、UI 或音频节点。
- 场景拥有局部状态；只有文档列出的服务可作为 Autoload。
- 信号连接必须有明确生命周期，退出房间后不留下监听。
- 静态定义使用字符串 ID，运行时实例使用独立 instance_id。
- 存档只保存数据，不序列化场景节点。
- 所有随机逻辑可注入 seed。
- 新增第三方依赖前先说明必要性、版本、许可证和替代方案。

## 5. 代码质量

- 一个脚本承担一个清晰职责。
- 优先组合，避免三层以上游戏对象继承。
- 对公共 API、复杂状态转换和非显然公式写说明。
- 不用注释重复代码表面含义。
- 不静默吞掉错误。
- 不提交持续错误、无关警告、临时代码和已失效 TODO。
- 不在任务中顺带大规模格式化或重构无关文件。

## 6. 测试规则

每个任务至少包含：

- 正常路径。
- 一个边界条件。
- 一个失败或无效输入条件。
- 任务验收中的人工检查。

战斗任务还必须检查：

- 左右朝向。
- 纵深边缘。
- 暂停恢复。
- 帧率波动或固定 tick。
- 多目标。
- 状态退出和对象释放。

存档任务必须使用测试目录和测试数据，不破坏真实存档。

## 7. Debug 与 Release

- Debug 构建可提供碰撞框、状态、AI 分数和帧数据。
- Release 构建不得显示或允许进入调试功能。
- 调试开关使用统一服务或构建特性，不在场景里散落判断。
- 临时占位资源必须在文件名和资源登记中标明 placeholder。

## 8. Definition of Done

任务完成必须同时满足：

- 只实现该 Backlog ID 的范围。
- 自动化测试通过。
- 人工验收通过。
- Godot 工程无新增错误或持续警告。
- Windows Debug 构建可启动。
- 相关文档和资源字段同步。
- 新增资产和第三方依赖已登记许可证。
- 向交接者报告修改文件、验证结果、已知限制和下一项未完成任务。

## 9. 遇到不清楚的需求

先按以下顺序处理：

1. 查 README-HANDOFF.md 的冻结决策。
2. 查当前里程碑退出条件。
3. 查战斗或技术架构文档。
4. 选择不扩大范围、可逆、可测试的最小实现。
5. 仍会显著影响产品或架构时，暂停并提出一个具体决策问题。

不要用自行增加大型系统来填补不确定性。

## 10. 提交说明

提交信息建议：

    feat(CMB-003): add hitbox deduplication
    test(SAV-001): cover interrupted atomic save
    fix(RM-003): clear room signal bindings on exit

合并请求说明必须包含：

- Backlog ID。
- 实现摘要。
- 明确未实现内容。
- 自动化测试结果。
- 人工测试步骤与结果。
- 截图或视频，仅在视觉任务需要时。
- 新增许可证或资产来源。
