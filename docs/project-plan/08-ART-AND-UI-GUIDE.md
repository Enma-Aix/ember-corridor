# 美术、动画、VFX、音频与 UI 规范

## 1. 视觉方向

工作风格：高精度像素角色加手绘分层背景。

视觉关键词：

- 工业奇幻。
- 清晰剪影。
- 暖色据点、冷色异常。
- 旧金属、布料、矿晶与能量纹路。
- 战斗信息优先于装饰。

原创要求：

- 不临摹 DNF 角色比例、职业服装、武器轮廓、技能图标或 UI 布局。
- 概念图生成提示中不得要求“完全像某个 DNF 角色”。
- 所有最终资源必须记录作者、来源、日期和许可证。

## 2. 角色规格

- 1080p 基准下玩家角色视觉高度约 128 至 160 像素。
- 只制作面向右的基础动画，面向左由引擎镜像；不对包含文字或不对称标记的元素直接镜像。
- 地面碰撞体明显小于角色视觉宽度，以脚部投影为准。
- 武器与身体可分层，便于换装和技能 VFX。
- 角色轮廓在灰度和 50% 缩放下仍可识别。

## 3. 动画清单

Vertical Slice 玩家最低动画：

| 动画 | 最低要求 |
| --- | --- |
| Idle | 6 至 10 帧循环 |
| Move | 8 至 12 帧循环 |
| Jump Start | 3 至 5 帧 |
| Airborne | 2 至 4 帧循环 |
| Landing | 3 至 5 帧 |
| Dodge | 6 至 10 帧 |
| Attack A1/A2/A3 | 每段独立关键姿势 |
| Air Attack | 起手、命中、恢复 |
| 8 个技能 | 每个独立动作或可靠复用骨架 |
| Hit Light/Heavy | 两种强度 |
| Knockdown/Get Up | 完整起倒 |
| Defeated | 简洁、非写实 |

动画按关键姿势优先制作：预备、挥击、接触、跟随、恢复。判定帧由战斗数据控制，但动作必须与判定视觉对齐。

## 4. 背景与房间

每个房间使用：

- 远景层。
- 中景结构层。
- 可战斗地面层。
- 前景遮挡层。
- 机关与交互层。
- 灯光和氛围层。

前景遮挡角色超过 20% 时应自动变淡或避免放置。战斗地面的可行走边界通过形状、材质或栏杆表达，不能只依赖隐形墙。

## 5. 颜色语言

| 信息 | 颜色方向 | 辅助形状 |
| --- | --- | --- |
| 玩家普通攻击 | 暖白、淡金 | 短弧 |
| 玩家职业能量 | 青蓝或职业专色 | 圆形/线条 |
| 敌方普通危险 | 橙 | 实线边缘 |
| 敌方高危险 | 红橙 | 加粗边缘与方向箭头 |
| 可交互 | 青绿 | 菱形图标 |
| 恢复 | 绿色 | 十字或上升粒子 |

任何关键信息必须同时使用颜色和形状，照顾色觉差异。

## 6. VFX 分层

每次攻击最多使用：

1. 武器拖尾。
2. 接触火花。
3. 命中闪光。
4. 少量碎片或能量粒子。
5. 地面或空气波纹。

普通攻击避免同时使用全部五层。重击和终极技能才使用完整层级。

VFX 限制：

- 不遮挡敌人预警。
- 不使用持续大面积纯白闪烁。
- 最低特效档仍保留危险范围和命中确认。
- 屏幕闪光强度受可访问性设置控制。

## 7. UI 设计

UI 风格为清晰的工业仪表与回廊符号，不使用现有游戏的技能栏框架或字体。

Figma 的阶段安排、文件结构、交付标准和设计冻结条件以
[12-FIGMA-UX-UI-WORKFLOW.md](12-FIGMA-UX-UI-WORKFLOW.md) 为准。本文件定义视觉原则，
Figma 文件定义已冻结界面的布局、组件、状态和交互，Godot 实现不得自行改变两者。

### 7.1 HUD

左上：

- 玩家头像或职业符号。
- 生命值。
- 等级。

右下：

- 四个技能槽和冷却。
- 终极能量。
- 键位提示自动随输入设备切换。

右上：

- 房间目标。
- 小型方向提示，不做复杂小地图。

中央：

- 首领生命与阶段提示。
- 短时教程和机制文本。

### 7.2 主要界面

- 主菜单。
- 存档槽。
- 选关。
- 技能配置。
- 装备与背包。
- 工坊。
- 图鉴。
- 暂停。
- 设置。
- 结算。

每个界面都要定义默认焦点、返回行为和手柄导航顺序。

## 8. UI 状态

每个列表和面板必须设计：

- 正常。
- Hover。
- Focus。
- Pressed。
- Disabled。
- Loading。
- Empty。
- Error。

不得只为鼠标设计 Hover，不提供手柄 Focus。

## 9. 字体

- 使用明确允许游戏内嵌和商业发行的字体。
- 中文至少覆盖常用简体字符和标点。
- 正文 1080p 不低于 22 px 的等效视觉大小。
- 字幕和教程允许用户调整 80%、100%、120%、140%。
- 发布包在 licenses/fonts 中保留许可证文件。

## 10. 音频方向

音乐：

- 灰港：低密度、温暖、可长时间循环。
- 地下城探索：环境层加轻节奏。
- 战斗：增加打击与节奏层。
- 首领：阶段变化增加层，不频繁硬切曲目。

音效：

- 每种攻击强度有独立瞬态。
- 敌人危险动作拥有在混音中可辨识的提示音。
- UI 音效短、柔和、不与战斗提示混淆。
- 同类命中音至少准备 3 个轻微变体。

命名只用小写英文、数字和下划线。工作源文件和游戏导出资源分目录保存。

## 12. 导入与压缩

- 像素资源关闭不必要过滤，具体按最终风格统一。
- UI 图标保留透明边缘，检查缩放时的锯齿。
- 音效优先 OGG 或 WAV，短促且需精确响应的关键音效可用 WAV。
- 背景大图按房间拆分，避免加载未显示区域。
- 每个区域建立资源预算并在实际目标机上检查显存和加载时间。

## 13. 占位资源策略

- 灰盒阶段只使用项目原创几何形状、纯色贴图和明确标注的占位音效。
- 占位资源文件名包含 placeholder。
- Release 构建前自动扫描并阻断仍引用 placeholder 的场景。
- 不从已发行游戏提取素材作为“临时资源”。

## 14. 美术验收

- 50% 缩放仍能区分玩家、普通敌人、精英和首领。
- 黑白截图仍能看懂主要攻击预警。
- 最低特效设置下战斗机制完整可读。
- 动画接触帧与 Hitbox 有效期对齐。
- UI 在 1280×720 与 1920×1080 无截断。
- 手柄焦点始终可见，无焦点陷阱。
- 所有正式资源均在资产清单中登记授权。
