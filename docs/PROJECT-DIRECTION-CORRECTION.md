# 《余烬回廊》方向纠正记录

## 结论

当前 M1 工程不是经过完整 DNF 品类研究后形成的产品原型，而是一套偏通用 2D 动作战斗的技术沙盒。它可以保留为移动、输入缓冲、连段、判定、伤害、浮空与命中反馈的底层验证，但不能继续充当正式游戏方向基准。

## 已确认的偏差

| 维度 | 原目标应验证的结构 | 当前工程 |
| --- | --- | --- |
| 战斗空间 | 横向推进、Y 轴纵深走位、独立视觉高度的房间制战斗 | 已有 X/Y 地面移动和视觉高度，但只有单个灰盒竞技场 |
| 关卡节奏 | 房间进入、清敌、封门、解锁、分支与首领房 | 未实现 |
| 产品循环 | 城镇准备、进入副本、战斗、结算、成长、再次挑战 | 未实现 |
| 职业系统 | 明确职业定位、技能树、资源循环与技能栏构成 | 只有三连段和一个测试技能 |
| 敌人与副本 | 普通怪、精英、首领的编队、机制与副本主题 | 只有无 AI 训练目标 |
| 联机定位 | 是否单机、合作或其他模式及其系统影响 | 早期直接冻结为离线单机，未先做目标验证 |
| 视觉与音频 | 镜头、角色比例、分层场景、特效、打击音与音乐的联合验证 | 只有原创几何占位表现；概念图未进入运行时 |
| 参照研究 | 类型拆解、竞品矩阵、录像逐帧、可玩样例和验证结论 | 缺失 |

## 当前版本的处理

- `v0.1.1-m1-tech-preview` 标记为旧方向技术预览。
- 保留可复用的确定性 fixed-tick 战斗底层与自动化测试。
- 不把当前场景、镜头、UI、职业、关卡或美术作为正式版本基准。
- 不复制 DNF 的素材、名称、角色、地图、音乐、代码或受版权保护的具体表现；后续只做类型结构学习与原创实现。

## “完整调研”的准确含义

这里的调研不是只阅读 DNF 的介绍或列出它有哪些系统，而是先建立同类产品池，对多款已经发行的游戏做基于证据的深度拆解和横向比较。

候选产品池必须先核验其实际玩法，再按相关度分层：

- 核心同类候选：DNF/DFO、Dragon's Crown、Closers、Elsword 等房间制或横版动作 RPG。
- 战斗空间参照候选：Streets of Rage 4、River City Girls 2 等带纵深清版动作游戏。
- 反向对照候选：Dead Cells、Hollow Knight、DNF Duel 等平台动作或纯格斗产品，用来明确不能继续混淆的类型边界。

每款入选产品都必须至少覆盖：

1. 实际战斗空间：镜头、横向推进、纵深宽度、跳跃/视觉高度、碰撞和锁定规则。
2. 房间结构：进入、封门、刷怪波次、清场、分支、精英、首领和离场节奏。
3. 操作与战斗：普攻、技能栏、冷却/资源、取消、连招、受击、浮空、倒地和容错。
4. 内容与成长：职业定位、技能成长、装备掉落、养成目标和重复游玩的驱动力。
5. 完整循环：城镇准备、组队或单人进入、副本推进、结算、强化和再次挑战。
6. 表现生产：角色比例、场景分层、动画数量、VFX、打击音、环境音、音乐和 UI 信息密度。
7. 产品与技术：单机/联机定位、关卡数据组织、同步要求、内容生产成本和可扩展性。

调研交付物必须包含逐款产品卡、来源与证据、横向矩阵、关键流程图、可借鉴规则、不可复制内容、风险/成本结论和对本项目的明确取舍。只给概括性结论、凭印象列功能或只研究一款游戏，都不算完成。

## 正式开发恢复门禁

在下一条正式玩法工单开始前，必须一次性完成并评审以下内容：

1. 同类产品池：完成核心同类、空间参照和反向对照的筛选依据。
2. 深度产品卡：逐款完成玩法证据与上述七类拆解，不用宣传文案代替实际系统研究。
3. 横向结论：形成参照矩阵，明确我们采用、修改、放弃的规则及原因。
4. 类型定义：明确“带纵深横版房间制动作 RPG”的空间、镜头、输入和碰撞模型。
5. 原创边界：建立“可借鉴的类型规则”和“不可复制的具体内容”清单。
6. 最小可玩验证：先做一个房间与一套职业操作，验证空间和手感，不能直接扩成完整工程。
7. 垂直切片方案：验证通过后才设计城镇准备点、三个连续房间、普通怪、精英与首领阶段。
8. 综合验收：确认镜头、纵深走位、技能密度、敌人编队、受击反馈和完整进出副本循环后，才恢复正式内容生产。

任何一项缺失时，只允许做研究或一次性验证，不进入正式内容生产。
