# CMB-005 生命、韧性、破防与受击反应

## 范围

- `CombatReactionProfile` 是可由 DataRegistry 校验的 typed Resource，分别提供普通、精英和首领策略。
- `CombatantModel` 持有运行时身份、阵营、防御、生命、韧性、反应和固定 tick 计时器。
- `CombatantModel.apply_damage` 是公式结果应用到目标状态的唯一入口；CMB-003 碰撞回调和 CMB-004 公式层仍不直接修改目标。
- `HitResult.with_application_outcome` 生成新的不可变结果，记录实际韧性伤害、破防、反应和击退，不回写原公式结果。
- 训练沙盒中的目标 A 使用普通策略和 25 防御；目标 B 使用精英策略和 100 防御。
- 本任务不实现浮空、倒地、追地、反无限连、动画、VFX、音频或正式敌人 AI。

## 固定 tick 规则

- 工程逻辑频率为 60 Hz。
- 受到大于 0 的韧性伤害后，恢复延迟重置为 180 tick；第 179 tick 仍不恢复，第 180 tick 开始恢复。
- 当前韧性归零时进入 `poise_break`，持续时间由目标的反应配置定义。
- 破防期间继续承受生命伤害，但不重复扣除韧性或重复触发破防。
- 破防最后一 tick 结束时韧性回满，并开始 60 tick 的韧性伤害减免。
- 减免倍率与每 tick 恢复量由目标配置；生命、韧性和治疗都限制在 `[0, maximum]`。
- 固定 tick 只在调用 `advance_tick` 时推进；暂停式渲染帧或不同渲染帧率不会改变状态。

## 三种配置策略

| 策略 | 未破防的普通命中 | 破防 tick | 恢复/tick | 破防后韧性倍率 | 特定破防标签 |
| --- | --- | ---: | ---: | ---: | --- |
| 普通 | `hit_stun` 12 tick | 45 | 1.0 | 0.50 | 无 |
| 精英 | 保留当前动作 | 90 | 0.75 | 0.50 | 无 |
| 首领 | 保留当前动作 | 60 | 0.50 | 0.35 | `reaction.boss_break` |

这些数值是首轮灰盒基线并保存在 Resource 中。固定的 180 tick 恢复延迟和 60 tick 破防后保护来自冻结战斗规则，不由单个敌人覆盖。

## 反应优先级

1. 目标生命归零时进入终止的 `defeated`，不再接受命中或治疗。
2. 特定破防标签或当前韧性归零时进入 `poise_break`。
3. 普通策略在未破防时进入 `hit_stun`；精英与首领保留动作。
4. 不满足以上条件时反应为 `none`。

方向击退来自不可变 DamagePacket 的方向快照和目标配置。首领默认击退为 0；浮空和倒地留给 CMB-006。

## 拒绝与事务边界

- 未配置或已失败的目标、无效 DamagePacket、被拒绝/无效/不匹配的 HitResult 都返回稳定拒绝码。
- 被拒绝的应用不会部分修改生命、韧性、反应或计时器。
- 配置先完整校验再替换运行时状态；失败的重新配置不会破坏已有目标。
- 反应配置在 `configure` 时深复制，源 Resource 后续修改不会改变战斗中的目标。
- `defeated` 只发出一次；训练沙盒在收到终止结果后关闭对应 Hurtbox。
- Hurtbox 的逻辑接收标志立即关闭；monitoring、monitorable 和 CollisionShape2D 使用 deferred 修改，避免在 Area2D 查询回调中触发 physics flush 错误。

## 自动化验证

- 三份反应 Resource 的身份、策略、数值、重复/空标签和非法边界，并由 DataRegistry 索引为 5 份项目定义。
- 普通目标承受 88 生命伤害、12 韧性伤害和 12 tick `hit_stun`。
- 精英第一次命中扣血但保留动作，第二次韧性归零后进入 90 tick 破防。
- 首领普通命中不反应；特定标签或普通伤害将韧性清零时进入 60 tick 破防。
- 破防第 89/90 tick、回满、60 tick 保护以及保护期内实际韧性伤害减半。
- 韧性恢复第 179/180 tick 边界、恢复上限以及暂停式帧不推进。
- 致命伤害、一次性终止信号、失败后拒绝、治疗量和生命上限。
- 配置事务性、包/结果一致性、资源快照、240 tick 双实例确定性和 WeakRef 释放。
- 真实 Area2D 沙盒一次 A1 对两个目标分别应用 88 与 55 生命伤害，并让精英进入破防。
- 连续攻击至两个目标失败后，Hurtbox 停止接触；再攻击不增加接受数或应用数，测试日志不得包含 Godot runtime error。
- Linux 与 Windows 原生 Godot 测试，以及 Windows 导出 EXE 启动。

## 人工验收

1. 使用 Godot 4.7.1 Debug 构建启动 `scenes/tests/movement_sandbox.tscn`。
2. 确认日志包含 `[CombatantSandbox] CMB-005 combatant reactions ready`，且无持续错误或警告。
3. 面向两个训练目标按 J / XInput X，确认总伤害仍为 143。
4. 确认 HUD 显示普通目标 `HP 212/300 · Poise 12/24`，精英目标 `HP 245/300 · Poise 0/12 · poise_break`。
5. 重复攻击，确认生命持续扣除、同一 hit_id 不重复应用，失败目标停止接受新接触。
6. 等待普通目标 3 秒，确认韧性开始恢复；等待精英破防结束，确认韧性回满。
7. 暂停后等待，再恢复，确认生命、韧性和反应 tick 没有在暂停期间推进。
8. 确认 Release 构建隐藏调试 HUD，但启动日志、资源加载与战斗状态无错误。
